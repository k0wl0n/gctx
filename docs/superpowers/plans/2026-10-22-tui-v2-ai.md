# TUI v2, AI Tools and AI Gateways Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the long-term TUI (slots, provider tabs, grouped list, detail pane, palette, login and create flows) and add AI tools (Claude Code, Codex) and AI gateways (OpenRouter, SumoPod, any OpenAI-compatible endpoint).

**Architecture:** Extends the provider contract from the multi-cloud plan with category, badge, slot, columns and form metadata. The manager tracks one active account per slot. The TUI renders everything from that metadata, so AI providers need no TUI special cases. Gateway API keys are stored as references and resolved only into child-process env (`pkg/secretref`).

**Tech Stack:** Go 1.26, cobra, bubbletea v2 / bubbles v2 / lipgloss v2. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-22-tui-v2-design.md` (on top of `docs/superpowers/specs/2026-10-21-multi-cloud-design.md`).

## Sequencing with the multi-cloud plan

1. Multi-cloud plan Tasks 1 to 7 (config schema, provider contract, GCP extraction, dispatch, CLI, AWS, Azure). Task 8 (Tencent) can land at any point; it is blocked only on its own spike.
2. **This plan, Tasks 1 to 14.** Multi-cloud **Task 9 is superseded** by Tasks 3 to 10 here; do not implement it.
3. Multi-cloud Task 10 (rename and docs sweep) last.

Before Task 1, confirm the working tree is clean (`git status`): commit or stash unrelated local edits first.

## Global Constraints

- Branch `feat/tui-v2` from the multi-cloud branch once its Task 7 is merged; one Conventional Commit per task, lowercase imperative subjects.
- No new Go dependencies; `go.sum` unchanged. Key helpers are external CLIs (`op`, `gcloud`, `security` on macOS, `secret-tool` on Linux) called through `provider.Runner`.
- Secrets (spec D13): no key, token or resolved secret in `config.json`, the status cache, logs, debug logs, stdout, golden files or error messages. Every task that touches gateways adds a test that greps output and logs for the fake key value and expects no match.
- `Overview()` stays file reads only. Anything that runs a CLI or calls the network lives in `CheckCredentials` or an explicit action.
- Timeouts and network errors map to UNVERIFIED, never AUTH REQUIRED (spec D14).
- A missing provider CLI or helper affects only that provider's rows.
- Existing key bindings keep their keys (spec "Keys"). `keyMap` stays the single source for dispatch, hint line, help and palette.
- Layout is tested by rendering at fixed widths (160, 120, 90, 70) and asserting on text, never on exact ANSI.
- Tests use fake CLIs following `internal/testutil/fakegcloud`; no test calls a real cloud, AI tool or gateway. Gateway HTTP is tested against `httptest.Server`.
- Every task updates the docs it touches; Task 14 does the sweep.

## Review Focus

1. A config with only `active_account` loads with the `gcp` slot set and round-trips; activating a SumoPod account replaces an active OpenRouter account in the `openai-api` slot (Task 2).
2. A hung auth check yields UNVERIFIED with the cached last result and age, never AUTH REQUIRED (Tasks 1, 4).
3. At 160/120/90/70 columns, NAME and STATUS are always visible and columns drop in the spec's order (Task 3).
4. `cctx env <gateway>` prints a lookup command, never the key; `run`/`shell` children get the resolved key; nothing else ever sees it (Tasks 12, 13).
5. A linked AI-tool account shows the cloud account's health, and deleting that cloud account is refused (Tasks 8, 11).
