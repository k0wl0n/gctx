**Cross-platform StartShell() with pwsh/cmd fallback on Windows and non-fatal ADC restore in SwitchAccount() so 'gctx current' always shows the correct account**

## Accomplishments
- StartShell() now detects the shell via runtime.GOOS on Windows, trying pwsh.exe, powershell.exe, COMSPEC, then cmd.exe as fallback; /bin/sh used on all other platforms
- SwitchAccount() no longer returns early when ADC credentials are missing; instead prints an actionable warning pointing the user to `gctx login`
- m.config.SetActive(name) is now always reached in SwitchAccount(), fixing the "gctx current returns unknown" bug

## Decisions Made
- Chosen Windows shell preference order: pwsh.exe (PowerShell Core) > powershell.exe (Windows PowerShell) > COMSPEC env var > literal "cmd.exe". This prioritizes the modern cross-platform shell while maintaining backward compatibility.
- ADC missing is treated as a degraded-mode warning rather than a hard error because the account config and gcloud configuration are still valid and usable; only ADC-dependent tools (like application-default credential consumers) are affected.
